## 4. 영어·한국어 개념 강의

### 4.1 Tool Contract·MCP — 도구 계약과 연결 규약

tool(도구)은 모델이 호출할 수 있는 명시적 기능이다. MCP, Model Context Protocol(모델 컨텍스트 프로토콜)은 도구·자원 연결을 표준화하는 규약이다. 표준 인터페이스가 있다고 도구 호출의 권한과 안전성이 자동으로 보장되지는 않는다. 허용 기능·입력/출력·인증 컨텍스트·부작용·실패 의미를 도구 계약에 적는다.

**업무 예시:** 정책 검색은 읽기 도구, 검토 결정은 쓰기 도구다. 두 도구에 같은 권한을 주지 않고 서버에서 역할과 tenant를 확인한다.

**직접 할 일:** 도구별 계약·권한·side effect(부작용) 표를 만들고 허용되지 않은 호출·인수·tenant를 거부한다.

### 4.2 ReAct·Plan-and-Execute — 추론과 실행 경로

ReAct는 Reasoning and Acting(추론과 행동)을 결합한 명칭이다. plan-and-execute(계획 후 실행)는 계획을 세우고 단계를 수행하는 구조다. reflection(성찰)과 추가 에이전트는 호출 횟수·지연·비용을 늘릴 수 있다. orchestration(오케스트레이션)은 단계·분기·실패·중단을 조율하는 시스템이며 모델의 판단과 실행 제어를 구분해야 한다.

**업무 예시:** 같은 실패를 반복해도 모델이 스스로 멈춘다고 가정하지 않는다. max_steps·허용 도구·전체 시간 예산을 실행 코드가 강제한다.

**직접 할 일:** 한 그래프를 정상·도구 실패·무한 반복 유도 입력으로 실행하고 종료 이유·각 도구 호출을 기록한다.

### 4.3 Async·Cancellation — 비동기 처리·취소

asynchronous processing(비동기 처리)은 대기 중 다른 작업을 진행할 수 있게 하는 실행 방식이다. async/await 표기만으로 모든 작업이 병렬화되거나 내구성이 생기지 않는다. timeout(시간 초과)과 cancellation(취소)은 자원 정리·상태 갱신·후속 행동까지 포함해 처리한다. 실행 중 외부 쓰기가 이미 성공했을 가능성도 있어 단순 재시도가 위험하다.

**업무 예시:** 모델 호출을 취소했어도 DB 연결이나 도구 작업이 계속 남으면 다음 요청에 영향을 준다. 중단 이유와 완료 여부 불확실성을 저장한다.

**직접 할 일:** Real-world asyncio의 취소·시간 초과 부분을 보고 현재 FastAPI 공식 문서로 코드를 확인한다. 지연·취소를 주입해 연결 정리와 상태를 검사한다.

### 4.4 Idempotency·Retry — 멱등성과 재시도

idempotency(멱등성)는 같은 요청을 반복해도 의도한 업무 효과가 한 번인 성질이다. idempotency key(멱등 키)는 같은 업무 요청을 식별하고 중복 실행을 방지하는 값이다. retry(재시도)는 일시 실패에만 횟수·시간 한도를 두고 backoff(대기 간격 증가)와 jitter(분산된 무작위 지연)를 적용한다. 입력 오류·권한 거부는 그대로 재시도해도 해결되지 않는다.

**업무 예시:** 검토 승인이 저장됐지만 응답이 끊겼을 수 있다. 재요청에서 같은 결정·감사가 두 번 생기지 않아야 한다.

**직접 할 일:** 재시도 가능/불가 표와 중복 요청 사례를 만든다. 성공 여부가 불확실한 외부 쓰기는 조회·조정 경로를 먼저 설계한다.

## 5. 확인 퀴즈

### Q1. MCP를 쓰면 권한 확인이 필요 없는가?

**해설:** 규약과 인가는 별도다. 서버에서 허용 도구·사용자·tenant·쓰기 권한을 검사한다.

### Q2. async 함수로 바꾸면 재시작 후 작업도 복원되는가?

**해설:** 비동기 실행과 지속 상태/내구성은 다르다. 작업 기록·재개·중복 방지 경로가 필요하다.

### Q3. 실패한 쓰기 요청은 모두 재시도해도 되는가?

**해설:** 외부 효과가 이미 발생했을 수 있으므로 멱등성과 결과 확인·조정 정책이 필요하다.
